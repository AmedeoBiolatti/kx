# Working in this repository with kx

kx is this competition's ledger and its door to Kaggle: runs, scores, findings, tasks and submissions go through
it, so whoever works here (a person, the agent they talk to, background workers) sees the same state.

## Start here

- `kx status`: what is running, what needs the person driving, best results, submissions, budgets.
- `kx context`: everything an agent needs before starting (your task, the reference protocol, best runs, open
  tasks, recent findings, these rules), in about 50 lines.
- `docs/competition.md`: the competition pages (generated by `kx meta`; do not edit).

Every command takes `--json`. Exit codes: 0 ok · 1 error (read the `fix:` line) · 2 usage · 3 needs confirmation ·
4 over a budget or a Kaggle limit · 5 not comparable.

## Where things go

| | |
|---|---|
| `src/comp/evaluate.py` | the evaluation protocol: **the one place a score is defined** (`from comp.evaluate import protocol`) |
| `src/comp/` | the rest of the importable code (features, models, data loading) |
| `scripts/` | entry points, each run with `kx exec -- python scripts/<name>.py` |
| `notebooks/` | exploration; conclusions go in findings, results in runs |
| `kernel/` · `agent/` | what Kaggle runs: the notebook (code competitions) or `main.py` (simulations) |
| `data/` | the competition data: a link into `.kx/store/data`, never in git |
| `.kx/` | kx's store (ledger, runs, artifacts, data) and the task worktrees, git-ignored |

Large outputs go in run dirs (`r.artifact(...)`, `kx path R`), never in git. Never run `git clean -x` (or `-X`) in the
main checkout: it would delete `.kx/`, the ledger and every run with it.

## Runs and scores

```python
import kx
from comp.evaluate import protocol
PROTOCOL = protocol()   # e.g. kx.Protocol("cv5", metric="auc", data=kx.data_version(), folds="v1", noise="cv")

with kx.run("what this run tests", config=cfg, seed=cfg["seed"], tags=["algorithm"]) as r:
    for epoch in range(cfg["epochs"]):
        r.progress(epoch + 1, total=cfg["epochs"], phase="train", loss=train_one_epoch())
    fold_scores = evaluate(model)                       # {"fold0": 0.81, ...}
    r.score(mean(fold_scores.values()), PROTOCOL, breakdown=fold_scores)
    preds.to_csv(r.artifact("submission.csv"))
    r.note("+0.004 over r0012, only on folds 2-3")
```

- Any command, any language: `kx exec -H "hypothesis" [--gpus 1] -- ./train --cfg x.yaml`. It sees `KX_RUN_DIR`;
  write `scores.json` there (`[{"protocol": "cv5", "spec": {...}, "value": 0.81, "breakdown": {...}}]`). A tqdm bar
  becomes the run's progress. Python under `kx exec` can use `kx.run(...)`: it attaches to the same run.
- Another machine: `kx exec --on HOST [--detach] -- cmd` (`kx remote list`, `kx remote check HOST`). Same run,
  same files; it reads the data through `kx.data_dir()`, which there holds the competition's own files only: a run
  that reads a cache under `data/derived/` asks for it with `--needs derived/NAME`. Detached: `kx remote follow R`,
  `kx remote sync`, `kx remote kill R`. Files over 32 MB (checkpoints) stay on the host: `kx fetch R [PATH]`. A paid
  host costs money: say so before starting a long run there.
- **Commit first.** An experiment refuses uncommitted code. `--probe` (`kind="probe"`) runs anyway and saves the patch.
- **Scores are comparable only under the same protocol id** (`name@fingerprint`, a hash of everything passed to
  `kx.Protocol`). One protocol is the **reference**: `kx board`, `kx status` and `kx context` rank under it
  (`kx protocol list`, `kx protocol use NAME`). Scoring under a new name is a side evaluation. Never edit the
  reference protocol to make a run look better; re-score older runs when it has to change (`kx.score(run, ...)`).
- **Log so runs can be compared**: the dashboard lines runs up in columns and charts.
  - Every setting goes in `config=` (nested dicts are fine) and the seed in `seed=`. They become the runs table's
    columns, and runs that differ only in their seed are drawn as one line with their range.
  - Curves: `r.step(i, loss=..., val_auc=..., samples=n_seen)`, with a counter (samples, epoch) beside the values,
    so runs that count steps differently line up on it. `r.progress(...)` with values logs them too.
  - Final numbers: `r.log(train_time_s=..., peak_mem_gb=...)`.
  - Code that logs to wandb or MLflow is recorded as it is (under `kx exec` and inside `kx.run`): keep it, do not
    log the same numbers twice. wandb sends nothing from a kx run unless `KX_WANDB=also`. Scores still need
    `r.score(...)` (or `scores.json`): a logged `val_auc` is a metric, not a score under a protocol.
- `kx compare A B` (paired test on the breakdown), `kx show R`, `kx runs`, `kx board`, `kx search WORDS`.
  `kx show R --json --curves` gives a run's curves cut to their shape (each stretch's first, last, lowest and
  highest point); every point is in `metrics.jsonl` under `kx path R`.

## Other machines

Other machines and people share this ledger through `kx sync`: it sends what this machine wrote, brings theirs, then
fetches Kaggle results (read-only). An agent working with a person runs it before `kx context` when starting a task
and after finishing one, so the others see its runs and findings. Workers (`KX_AGENT` set) leave syncing to the person:
their sandbox hides rclone's login. If `kx status` says this machine lost a task's claim (another machine started
it first), stop working on that task: a `kx task done` or `wait` from here no longer changes it. In anything others
read, write full ids (see below).

## Tasks and findings

- `kx task list`, `kx task add "..." --body "..."`, `kx task show T7`, `kx task start T7` (your runs are linked to
  it until it is done), `kx task note T7 "progress..."`, `kx task wait T7 --on run:r12` (or `submission:S4`, `T3`, a
  command for the person, text), `kx task done T7 --result positive|negative|inconclusive --outcome "..."`.
  Negative results are results: say what was tried and what was learned.
- `kx search` before trying an idea. Conclusions go in findings, with the runs that support them:
  `kx finding add "fold 3 leaks through user_id" --evidence r12 r15 --tag data`.
- Other machines and people read what you write. In notes, outcomes and findings write the full id
  (`r0012-fluent-sun`, `F3-bold-comet`): a bare `r12` means this machine's r12, and another machine may have one too.

## Kaggle

- `kx submit R -m "..." --why "what this tests" --expect "..."` builds the file as an immutable artifact,
  smoke-tests it, checks slots, duplicates and the ladder, and shows a **preview**. Nothing is sent without
  `--yes`. An agent working with a person asks them before passing `--yes`.
- `kx kernel push R` and `kx dataset push R PATH` work the same way. In the kernel code, `KX = "__KX_PUSH__"` becomes
  the JSON `{"run", "git_sha", "datasets": {ref: run}}` at push: compare it with each dataset's `kx-dataset.json`
  and fail if they differ (a kernel pushed before Kaggle finished processing a dataset gets its previous version).
- `kx sync` fetches results and a leaderboard snapshot; `kx subs` lists submissions with today's slots (and the
  ladder, simulations); `kx subs S12` shows one with its games.
- Workers (`KX_AGENT` set) do not send: with `--yes` kx refuses (exit 3) and prints the command. Record it with
  `kx task wait T7 --on "kx submit ... --yes"` and end the session; the person sees it in `kx status` and runs it.
- Never call `kaggle competitions submit` or `kaggle kernels push` directly: kx would not know about it.

## Budgets

`kx budget` shows the caps in comp.yaml `budgets:` (submissions, Kaggle GPU hours, local GPU hours from
`kx exec --gpus N`, worker tokens, `cloud_usd` for paid remote hosts), each with what it counts (the team, a person,
this machine). Over a cap, the action is refused with when it frees up (exit 4). Wait, or work on something that does
not need it.

## Data and files

- Data lives outside git, linked as `data/` in every checkout (task worktrees in `.kx/worktrees/` too). Use
  `kx.data_dir()`; put `data=kx.data_version()` in the protocol so a data update makes scores incomparable.
- Run artifacts live in the run dir (`kx path R`), not in git.
