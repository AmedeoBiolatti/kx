# kx v2

kx is the instrument a competition is worked with: a ledger of runs, scores, findings, tasks and submissions, the
rules that keep scores comparable, and the only door to Kaggle. It does not decide what to work on and does not run
anything on its own. A human drives, alone or with an interactive agent in their terminal (Claude Code, Codex); that
driver may start background **workers** for parallel tasks.

v1 (tag `v1`) grew into a closed system: an autopilot launching agents, approvals, roles, leases, contracts and a
13-tab dashboard. It stalled for a week on two approvals nobody saw while `kx unstick` said nothing was stuck. v2 keeps
what was used and makes the state legible from outside.

## What the v1 ledgers showed (2026-10-15, both competitions)

- 222 agent sessions, ~3,400 kx calls. 20% were bookkeeping (`task checklist` 456, `whoami` 174, `heartbeat` 65).
- `compare` was run 7 times, `validate` 17. Sweeps, solutions, fidelity, executions and checks tables are empty; the
  compute queue ran one job per competition.
- ptcg has 39 protocols for 73 scores: almost every task minted its own, so nothing was comparable.
- `main` held 1 commit; the 158 commits of work lived on `kx/integration`, with 122 branches and 39 worktrees.
- Competition code uses only `kx.run`, `Protocol`, `data_version`, `data_dir`, `run_dir`, `file_digest`,
  `current_run`, `score`, `winrate` and `r.score / note / artifact / archive / progress / step / log / log_text /
  log_table / log_image / declare_inputs / tag`. v2 kept that API; the 2026-10-24 cleanup (below) dropped the parts
  v2's own competitions never called.

## Principles

1. **A tool, not a runtime.** No supervisor, no autopilot, no planning rounds. Every command does one thing and
   returns. Waiting too: `kx wait` blocks until something has happened (or can no longer happen) and exits; the
   agent's harness, running it in the background, does the waking. Nothing is registered, so nothing is left behind.
2. **One question, one command.** `kx status` answers "what is going on and what needs me"; `kx context` gives an
   agent everything it needs to start in at most ~50 lines.
3. **Agent contract.** Every command takes `--json`. Text output is never truncated when it is not a terminal.
   Errors say how to fix them. Exit codes mean something (below).
4. **Gate only what leaves the machine.** Submissions and kernel/dataset pushes are previewed and need `--yes`.
   Workers cannot pass `--yes`: their external actions become requests the human confirms. Everything else is local
   and anyone may do it.
5. **Budgets refuse up front.** A cap is checked before the action and the action is refused with the reset time.
   It never turns into a request for the human.
6. **Plain git.** Work lands on `main` through normal merges. Worktrees only for workers running in parallel.

## Exit codes

| code | meaning |
|---|---|
| 0 | ok |
| 1 | error (message + `fix:` line) |
| 2 | bad usage (argparse) |
| 3 | needs confirmation: a preview was shown (rerun with `--yes`) or a request was filed for the human |
| 4 | refused by a budget or a Kaggle limit (message says when it resets) |
| 5 | not comparable (`kx compare`) |
| 6 | what `kx wait` waited for can no longer happen: the run failed, stalled or ended short of `--until`; the submission or kernel errored |

With `--json`, stdout carries one JSON document: the result, or `{"ok": false, "error", "fix", "code"}`.

## Actors

- **you**: no `KX_AGENT` in the environment. The human, or an agent the human is talking to. Full access; external
  actions need `--yes` after the preview. An interactive agent must ask the human before passing `--yes`.
- **worker** `KX_AGENT=<name>`: a background agent started with `kx spawn` (or by hand). Local actions only; an
  external action is refused (exit 3) with its command, which the worker records with `kx task wait T7 --on "<it>"`
  for the human to run. Its tokens are measured and budgeted.

## Concepts

- **Run**: one tracked execution (`kx.run(...)` or `kx exec -- cmd`): git sha (dirty = refused for experiments,
  patch saved for probes), env, config, seed, task, metrics, curves, progress, artifacts, notes, tags.
- **Protocol** `name@fingerprint`: scores are comparable only under the same id (unchanged from v1).
- **Reference protocol**: the one protocol that ranks runs (`kx protocol use NAME`; newest fingerprint of that
  name). `kx board`, `status` and `context` rank under it; other protocols are side evaluations and are listed as
  such. Without a reference kx says so and uses the most-scored protocol of the last 14 days.
- **Finding**: a conclusion with evidence runs and a status (open / withdrawn / superseded) and tags.
- **Task**: title, body, priority, depends, owner, status `open → active → done` (or `waiting` with what it waits
  on), result (positive / negative / inconclusive) and outcome. `kx task note` appends progress lines. Runs are
  linked to the task their author has active (or the worker's task, or a task branch).
- **Submission**: built from a run (immutable sha256 artifact, smoke test on the exact bytes, no duplicates), daily
  slots, ladder rule for rl competitions (a new submission must not retire one that has not played enough games),
  why/expect kept with the result. Code competitions submit the kernel version pushed for the run.
- **Budget**: caps in `comp.yaml` (`budgets:`) over a usage ledger: `submissions`, `kaggle_gpu_hours`, `gpu_hours`
  (local, wall time × GPUs of `kx exec --gpus N`), `tokens` (worker sessions), `cloud_usd` (remote hosts), per `day` (since 00:00 UTC) or `week`
  (rolling 7 days), per worker (`budgets.workers.<name>`) or, for the rest, over what the metric is paid from:
  the team (submissions), a person (Kaggle GPU hours, tokens, cloud USD), this machine (local GPU hours);
  `budgets.scope` changes that. A cap is hard: wait, or raise it. Kaggle's own limits always apply.
- **Remote run**: `kx exec --on HOST` runs on another machine, over ssh or through a mailbox (hosts in
  `~/.config/kx/hosts.yaml` or comp.yaml `hosts:`). kx ships a job folder (run.sh, the commit's code), the kx sources
  and the data's own files when the host lacks them; run.sh builds the env from `uv.lock` once per lock and runs the
  command, confined by bubblewrap. The run's out/ comes back (never deleting; files over 32 MB on request, `kx fetch`)
  while it runs or on `kx remote sync`; then it is recorded like a local run. On the host `KX_REMOTE=1`: `kx.run`
  writes scores.json / notes.jsonl / attach.json instead of the ledger.
  Paid hosts charge `cloud_usd`. `kx reap` leaves remote runs alone; `kx status` flags ones not synced for 30 min.
- **Worker**: `kx spawn T7 --harness codex --model M` creates the task worktree, writes the context, sets
  `KX_AGENT`, runs the harness in the background with its transcript in the store and token usage parsed live.
  `kx workers`, `kx stop W`. Token caps are checked at spawn and enforced while it runs. No retries, no supervisor.

## comp.yaml

```yaml
slug: <competition-slug>
kind: file | code | simulation
mode: predict | optimize | rl          # default: rl for simulation, else predict
metric: {name: mrr@25, direction: max}
reference: cv5                         # optional initial reference protocol (kx protocol use changes it)
submission:
  daily_limit: 5
  file: submission.csv
  kernel: user/kernel-slug             # code competitions
  kernel_dir: kernel
  smoke: python smoke.py {artifact}    # simulations default to a Kaggle-style load of main.py
  active: 2                            # rl: submissions that keep playing
  min_episodes: 30
budgets:
  submissions_per_day: 3
  kaggle_gpu_hours_per_week: 25
  gpu_hours_per_day: 12
  tokens_per_day: 30000000
  workers:
    codex-1: {tokens_per_day: 10000000}
runs: {on: [colab, lambda]}            # optional: the only hosts runs may use (the first is the default)
storage: {keep: here, max_gb: 200}     # optional: remote runs leave nothing on hosts; a cap on the store here
workers:                               # what kx spawn may start
  codex-1: {harness: codex, model: gpt-6-luna, effort: medium}
  sonnet-1: {harness: claude, model: sonnet}
tags: [algorithm, speed, data, eval, infra, bug]
```

## Commands

```
status [--all]                 what is running, what needs you, results, budgets
context                        what an agent reads first (also given to workers)

exec [-H HYP] [--probe] [--gpus N] [--tag T] [--on HOST] [--detach] -- CMD    track any command as a run
wait TARGET ... [--all] [--until COND] [--stall MIN] [--timeout MIN]   until a run (group:NAME) ends or meets COND,
                               S4 is scored, kernel:R ends; a run says its score, rank and verdict vs parent/best
remote list | add | check HOST | setup HOST | sync [R] | follow R | kill R   runs on other machines
runs | show R | board [PROTOCOL] | compare A B | search WORDS | fetch R [PATH]
note R TEXT | tag R TAGS [--rm] | path R | reap | gc [R ...] [--yes] | progress ...
protocol list | protocol use NAME

task add | list | show | start | note | wait | done | reopen | edit | merge | relink
finding add | list | show | withdraw | supersede

submit R -m MSG --why --expect [--yes]       build + smoke + checks + preview, then send
subs [S] | sync [--no-games] [--no-lb]
kernel push R [--yes] | kernel status [R] | dataset push R PATH [--yes]
budget

spawn T --worker NAME | workers | wait | stop W
init | meta | data [--status] | doctor | export [FILE] | import [PATH]
```

## Removed

autopilot, plan, steer, unstick, recover, chat/ask, notify, roles/policy/approvals matrix, validate/promote/review
stages, champion, leases/heartbeats/checklists, task revisions/contracts/requirements/outputs/checks, run contracts,
solutions, fidelity, sweeps, durable executions, checkpoint/resume/reproduce, audits, comparison workspaces,
capabilities, measurements, methods/research (sources), resources (systemd scopes), compute queue/worker, the
`kx/integration` branch, the v1 dashboard. They stay retrievable at tag `v1`.

The 2026-10-24 cleanup, from what two competitions' agents actually called, removed: the v1 migration (`kx migrate`),
worker requests (`requests`, `confirm`, `reject`: workers now leave the command to their person), `--over-budget`,
`diff`, `task drop`, `finding confirm` / `tag`, `slots` / `lb` / `episodes` (folded into `subs` and `sync`), hosts kx
starts itself (`remote up` / `down`, never given a real provider), `data: kaggle` and `data_cache` hosts, the replay
fallback for game results, the `events` table, and the run API `log_text`, `log_image`, `declare_inputs`,
`archive`, `r.tag`, `kx.winrate`, `kx.file_digest`.

## Phases

1. Core: ledger, tracking API, exec, runs/protocols/compare, tasks, findings, Kaggle (data, meta, submit, push,
   sync, ladder), budgets, status, context, KX.md. Autopilot gone.
2. Workers: spawn, transcripts, token budgets.
3. Dashboard: one page per question (Status, Runs, Tasks, Findings, Submissions) over the same JSON.
